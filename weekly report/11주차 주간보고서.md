## ✅ 이번주 진행사항 

### 🔹 개발상황 

멀티스레딩 기반 매핑 최적화 : 기존 단일 루프 구조를 Python threading 기반 멀티스레드 구조로 전환하여 처리 시간 40~55% 단축

QID 수집 및 위키데이터 연동 강화 : 위키데이터에서 법률·사건·인물 QID 직접 수집 및 신규 항목 수동 등록 다수 진행

프론트엔드 UI 시안 구현 : Figma 기반 메인 및 서브페이지 UI 구성 정리 및 Tailwind CSS 애니메이션 테스트 진행

CPA 모델 연계 분석 착수 : CTA 모델 외 TURL, DUDUO 등 유사 모델 비교 및 CPA를 위한 키워드 추출 방식 기획

### 🔸 팀 공통사항 

웹 시각화 구현을 위한 데이터베이스(DB) 구조 설계를 위해 팀 내 논의를 진행함. 지식그래프 형태의 시각화를 위해 체계적인 DB 구축이 선행되어야 하며, 어떤 방식으로 데이터를 정리하고 필드를 구조화할지에 대한 아이디어를 공유하기로함.
곧 있을 업체와의 미팅을 대비해 담당자에게 전달할 주요 질문과 논의할 주제들을 정리함. 기술 구현 방식, 제공 가능한 API 범위, 데이터 제공 형식 등을 중심으로 사전 질의사항을 준비함.
내부 논의 결과, 비대면 소통만으로는 세부 조율이 어렵다는 판단에 따라 외부 업체와의 대면 회의 필요성에 공감대를 형성함. 이에 따라 팀원 간 일정을 조율해 대면 미팅 일정을 조속히 확정할 예정임.

### 👤 개별 진행사항

#### 💡 권진호 

- 기존 단일 프로세스 기반의 엔티티 매핑 루프를 Python threading 기반으로 멀티스레드 구조로 개선
- 멀티스레드 환경에서도 모델 출력 결과가 일관되게 유지되도록 shared memory 접근 방식 재검토
- 각 스레드의 성능 모니터링을 위해 tqdm 병렬 처리 버전 적용 및 로깅 최적화
- 스레드 수에 따른 처리 속도 비교 테스트 진행 (4, 8, 16 threads)
- 처리 시간 약 40~55% 단축 확인 (케이스별 차이 존재)
- 메타데이터 기반으로 위키데이터 수동 등록 다수 진행
