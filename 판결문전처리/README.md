## 현재 컬럼
문제 1 : 이름과 한자가 완전히 동일한 인물이지만 서로 다른 사람일 수 있음

예: 곽태종(郭泰鍾)이 두 번 등장하지만 서로 다른 사건, 다른 생일, 다른 판결 -> 곽태종(郭泰鍾)_0509 vs 곽태종(郭泰鍾)_0909

문제 2:

동일 인물이 한 번은 서브 인물로 등장해 나이, 주소 등 정보 없이 처리됨
이후 다른 사건에서 메인 인물로 등장하여 정보가 새롭게 등장함
-> 서브 인물들은 다 삭제해서 해결함 인물이 워낙 많기 때문에 버리는게 맞다고 판단

### 고유 성명ID 생성 기준

- JSON 노드로 시각화 시, 고유 ID 필요.

- 단순 이름 사용 불가: 한자 포함, 동명이인 존재, 사건명이 너무 길고 중복됨.

➡️ 성명 + 나이 조합으로 고유 ID 생성.

- ❌ 성명 + 생일: 생일 없는 인물 많아서 제외.

- ❌ 성명 + 주거지: 주소 표기 방식이 달라서 중복 판별 어려움 (예: 경북 vs 경상북도) 정제한다면 주거지도 괜찮은 선택.

- ✅ 성명 + 나이: 현재까지는 나이 중복 발견 안 됨 → 가장 현실적인 기준.

## 구조체 구조 요약
```
[주소]
  └─▶ [년도]
        └─▶ [사건]
                ├─▶ [죄명]
                └─▶ [사람]
```

- 노드 간 관계는 `source → target` 방향으로 연결됨
- nodes + edges 방식 사용

---


## 🧾 구성 요소별 설계표

| 노드 종류 | URI 존재 여부 | 고유 속성 포함 여부 | 포함된 고유 속성 항목 예시                          |
|-----------|----------------|----------------------|----------------------------------------------------|
| **인물**  | ❌ 없음         | ✅ 있음               | `나이`, `주문`, `판결시점`, `본주거지`             |
| **주소**  | ✅ 있음         | ❌ 없음               | (`uri`만 존재, 추가 정보 없음)                    |
| **죄명**  | ✅ or ❌        | ❌ 없음               | (`uri`만 존재, 추가 정보 없음)                    |
| **사건**  | ❌ 없음         | ❌ 없음               | (`label`에 설명 포함, 별도 속성 없음)             |
| **연도**  | ❌ 없음         | ❌ 없음               | (단순 표시 목적, 추가 속성 없음)                  |

## 🧩 노드 설계 원칙

- 모든 노드는 고유한 `id`를 가짐.
- `성명`, `사건`은 텍스트만으로 구별하기 어려워서 고유 ID를 따로 생성.  
  예: `"N2959"` = 인물 ID, `"e002"` = 사건 ID
- 나머지 구성요소(`주소`, `죄명`, `날짜`)는 label 앞에 접두어를 붙여 ID를 구분했다.  
  예: `"addr_평북"`, `"crime_모살미수"`, `"date_1912"` (이때 년도만 뽑고 월단위는 인물 속성에 넣어놓은상태)


- `URI`는 Wikidata 기준 QID를 사용하는 방식이었지만,
  - 실제로 QID 수동 검색/검증에 시간이 많이 걸리고
  - 외부 연결 기능이 필요 없을 경우 내부용 고유 ID만으로 충분하다고 판단해서
  - 없는 경우는 전부 `null`로 처리하고, 필수값으로 간주하지 않도록 구성했다.



    

## 🔗 구조체 구성 예시
```
 1. nodes(인물, 주소, 연도, 사건, 죄명) 구성

{
  "key": "노드의 고유 ID",
  "attributes": {
    "label": "화면에 표시될 이름",
    "type": "노드 종류 (예: 인물, 주소, 죄명 등)",
    // 추가 속성들 (노드 종류에 따라 다름)
  }
}

2. edges 구성

{
  "source": "출발 노드 ID",
  "target": "도착 노드 ID",
  "attributes": {
    "label": "관계 설명",
    "size": 1
  }
}
```
3. 고유 ID 생성 및 중복 방지 처리
used = {} 딕셔너리로 노드 중복 생성을 방지

이미 한 번 생성된 노드는 중복 생성하지 않음

### 🔗 노드 간 관계 정의 (Edge 연결 구조)

| source 노드 | target 노드 | 관계 라벨   |
|-------------|--------------|--------------|
| 주소 노드    | 연도 노드     | 위치         |
| 연도 노드    | 사건 노드     | 시점         |
| 사건 노드    | 죄명 노드     | 혐의         |
| 사건 노드    | 인물 노드     | 관련인물     |
